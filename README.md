# 게임 공장 — 만들고, 재고, 버리는 반복

- 시작: 2026-11-25 · business 실험 ID: `E01` (`~/Desktop/NHC/agents/business/experiments/experiments.json`) · business 아이디어 `I01`
- 목적: 작은 게임을 계속 만들어 보고, 숫자로 남길 것과 버릴 것을 가른다. 한 판 더 하고 싶은 게임 하나를 찾을 때까지 반복한다
- 관리 보드: `board.html` (생성물, `python3 tools/build_board.py`) · 오락실: `arcade/index.html` (게임 목록 `arcade/catalog.js`는 `python3 tools/build_arcade.py`로 생성). 직접 고치지 않는다
- 단일 출처: `games.json`

## 1. 단계 (한 방향으로만 이동, 폐기는 어디서나)

```
아이디어 ──심사──▶ 프로토 ──1주──▶ 플레이테스트 ──판정──▶ 유지 ──▶ (스팀 페이지·데모 = 새 실험)
    │                 │                  │                 │
    └────────────────┴──────────────────┴──────▶ 폐기 (이유·레슨 필수)
```

| 단계 | 들어가는 조건 | 나오는 조건 | 폴더 |
|---|---|---|---|
| 아이디어 | 한 문장 + 점수 5칸 | 심사 점수 18/25 이상 → 프로토 | 없음 (games.json에만) |
| 프로토 | 폴더 생성, `brief.md` 작성 | 7일 안에 플레이 가능한 `game/index.html` | `G###_<slug>/` |
| 플레이테스트 | 5명 이상에게 플레이 | `playtest.md` 기록 → 판정 | 같은 폴더 |
| 유지 | '계속할 신호' 충족 | 다음 실험(스팀 페이지·itch.io 공개) brief | 같은 폴더 |
| 폐기 | '그만둘 신호' 또는 기한 초과 | — (`result.md`에 이유·레슨) | 폴더는 지우지 않는다 |

## 2. 겹치지 않게 하는 규칙

1. **동시에 진행하는 게임은 6개까지다.** 프로토와 플레이테스트 단계를 합쳐 6개(2026-11-26 사용자 결정: 오락실에서 여러 개 비교). 유지 단계는 최대 1개
2. **ID는 다시 쓰지 않는다.** `G001`, `G002`… 순서대로 매긴다. 폐기된 게임 폴더도 그대로 둔다(링크·레슨 보존)
3. **게임 하나 = 폴더 하나 = HTML 하나.** `game/index.html` 하나로 브라우저에서 바로 열린다. 설치·CDN·웹 글꼴 금지(오프라인 동작)
4. **공용 코드는 `_shared/`로 올린다.** 두 게임 이상에서 쓴 코드(효과음 합성, 입력, 화면 흔들림 등)만 올린다. 각 게임은 공용 코드를 복사해 넣는다(게임 폴더만 떼어 내도 돌아가게)
5. **기한이 판정이다.** 프로토 7일을 넘기면 자동 폐기 후보다. 연장은 1회 3일까지, 이유를 games.json에 남긴다
6. **같은 아이디어 변형은 새 ID다.** 폐기된 게임을 고쳐 다시 하면 새 ID에 `parent`로 연결한다

## 3. 심사 점수 (아이디어 → 프로토)

각 1~5점, 합계 25점. **18점 이상**만 프로토로 간다. 처음 점수는 Claude의 정성 판단이다. 사용자 점수가 있으면 그것을 쓴다.

| 칸 | 질문 | 근거 |
|---|---|---|
| 훅 | 한 문장만 듣고 "해 보고 싶다"가 나오나 | 하이 콘셉트 유형 |
| 클립 | 10초짜리 쇼츠·스트리머 화면으로 재미가 보이나 | 스팀 인디는 위시리스트·스트리머 싸움 |
| 반복 | 한 판 끝나면 바로 한 판 더 하고 싶나 | 중독성 유형 |
| 범위 | 1인 + AI로 7일 안에 핵심 재미까지 되나 | 1주 프로토 원칙 |
| 새로움 | 같은 한 문장 게임이 이미 넘치지 않나 | 포화 회피 |

## 4. 판정 기준 (가설, 첫 3개 결과로 고친다)

- **계속할 신호:** 테스터 5명 중 3명 이상이 시키지 않았는데 한 판 더 함, 또는 플레이 시간 중앙값 10분 이상
- **그만둘 신호:** 5명 중 1명 이하만 다시 함, 또는 한 문장 설명을 듣고도 뭘 하는 게임인지 모름
- 애매하면 **폐기**한다. 고치고 싶으면 새 ID로 다시 낸다

## 5. 폐기할 때 남길 것

- `result.md`: 숫자(테스터 수, 다시 한 사람 수, 중앙값), 왜 재미없었나 한 줄, 살릴 부품
- 살릴 부품은 `_shared/`로 옮긴다
- 레슨은 `domains/game/lessons.md`에 반영한다(lesson-keeper 몫)

## 6. 원칙

- 원작이 있는 게임을 이름·캐릭터·그림만 바꿔 다시 만들지 않는다. 장르나 메커닉을 참고하는 것은 괜찮다
- 외부 공개(itch.io·스팀 등록)는 **유지** 판정 뒤 사용자 확인을 받고 한다
- 재미 판정은 사람이 한다. Claude는 만들고, 기록하고, 숫자를 센다
