# 게임 밖 UI 정돈 기준 (시작·레벨 선택·HUD·결과·안내 카드·버튼·토스트·설정)

- 작성: 2026-11-27 · 대상: game-lab 단일 HTML 프로토(휴대폰 세로 우선, 오프라인, 시스템 글꼴)
- 목적: "게임은 좋은데 주변 UI가 후져 보인다"는 피드백 → 화려함이 아니라 **정돈·일관·정확**으로 공들인 느낌 내기
- 표기: **[사실]** = 출처에 적힌 내용 · **[판단]** = 출처를 바탕으로 한 이 문서의 권장(검증된 표준 아님)

---

## 바로 적용할 규칙 15개 (체크리스트)

1. [ ] **간격은 4의 배수만**: 4·8·12·16·24·32·48px 7단계. 13px·15px·17px 같은 값 금지
2. [ ] **글자 크기는 5단계만**: 12(보조) · 14(본문 작게) · 16(본문) · 20(카드 제목) · 28~32(화면 제목/결과 숫자). 한 화면에 3단계 이하
3. [ ] **굵기는 2개만**: 400(본문) · 700(제목·버튼). 600/800 섞지 않기
4. [ ] **줄 간격**: 한국어 본문 1.5, 제목 1.25, 버튼·HUD 숫자 1 (`line-height`)
5. [ ] **터치 영역 최소 48×48px, 사이 8px 이상**(아이 대상이면 56px 이상). 보이는 아이콘이 24px여도 누르는 칸은 48px
6. [ ] **모서리 반경 3단계**: 8px(작은 칩·토스트) · 12px(버튼) · 20px(카드·모달). 원형 버튼은 50%. 그 외 값 금지
7. [ ] **그림자 2단계만**: 떠 있는 카드 1종, 눌림 없는 버튼 1종. 테두리와 그림자를 한 요소에 같이 쓰지 않기
8. [ ] **색은 역할 5개**: 배경 · 면(카드) · 글자(진하게/연하게 2톤) · 강조 1색 · 위험/성공 각 1색. 강조색은 화면당 주 버튼 1개에만
9. [ ] **대비**: 본문 글자 4.5:1 이상, 큰 글자(24px+ 또는 19px 굵게)·아이콘·버튼 테두리 3:1 이상
10. [ ] **모션 시간**: 버튼 눌림 80~100ms, 토스트·작은 요소 150~200ms, 카드/모달 등장 225ms·퇴장 195ms, 화면 전환 300ms(400ms 넘기지 않기)
11. [ ] **이징 2개만**: 등장 `cubic-bezier(0,0,.2,1)`, 퇴장 `cubic-bezier(.4,0,1,1)`. `linear`·기본 `ease` 섞지 않기. `prefers-reduced-motion`이면 이동 끄고 페이드만
12. [ ] **눌림 피드백 100ms 이내**: `:active`에 `transform: scale(.96)` + 그림자 줄이기, `pointerdown`에서 바로 반응
13. [ ] **아이콘은 한 세트·한 크기·한 선 굵기**: 인라인 SVG(Lucide 또는 Tabler), 20/24px, `stroke-width:2`, `stroke="currentColor"`. UI 버튼에서 이모지 제거
14. [ ] **숫자는 고정폭**: 점수·타이머·레벨 번호에 `font-variant-numeric: tabular-nums` (숫자가 바뀔 때 흔들림 방지)
15. [ ] **기본 브라우저 스타일 지우기**: `button{appearance:none;border:0;font:inherit}`, `-webkit-tap-highlight-color:transparent`, `user-select:none`(게임 화면), `touch-action:manipulation`, 한국어 `word-break:keep-all`

> 위 수치 중 48px·8px 간격, 4.5:1·3:1, 225/195/300ms·이징 곡선, 0.1초는 아래 출처의 **사실**. 글자 5단계·굵기 2개·반경 3단계·그림자 2단계·색 역할 5개·아이 56px는 **판단**(작은 게임에 맞게 줄인 값).

**공통 원칙 [판단]** (위 사례 관찰 + 2·3장 수치 근거로 정리)
- **덜어내기**: 화면마다 할 일 하나, 주 버튼 하나. 시작 화면은 '플레이' 하나가 가장 크다
- **제한된 팔레트**: 게임 화면과 같은 색을 UI가 그대로 씀(UI 전용 색을 따로 만들지 않음). 강조 1색
- **글자 위계는 크기 차이로 크게**: 제목/본문 비율 1.5배 이상. 비슷한 크기 여러 개가 가장 싸 보인다
- **같은 모양 언어**: 모서리·선 굵기·그림자가 게임 안 도형과 같은 규칙(예: 게임 타일이 둥근 12px면 버튼도 12px)
- **모션은 의미 있을 때만, 짧게**: 등장은 감속, 퇴장은 가속, 한 번에 하나

## 2. 구체 수치와 근거

### 간격
- [사실] 8의 배수 간격이 업계 관행이며, 작은 요소 안쪽(버튼 패딩·배지)은 4, 요소 사이는 8 단위로 쓰는 혼합 방식이 흔함. 근거는 지각 연구가 아니라 "값을 줄여 일관성을 지키기"이고, 세밀한 값은 13·15·17px 같은 흐트러짐을 부른다는 경고가 있음 — [LogRocket](https://blog.logrocket.com/8-best-ways-define-component-spacing-design-system), [spec.fm 8-Point Grid](https://spec.fm/specifics/8-pt-grid), [UX Collective: 4pt grid](https://uxdesign.cc/goodbye-8-point-grid-hello-4-point-grid-1aa7f2159051)
- [판단] 화면 좌우 여백 16px(좁은 폰 375px 기준), 카드 안쪽 16~24px, 카드끼리 12px, 버튼 안쪽 위아래 12·좌우 20px

### 터치 영역
- [사실] Apple: 히트 타깃 최소 44×44pt — [Apple Design Tips](https://developer.apple.com/design/tips)
- [사실] Android: 최소 48×48dp(약 9mm), 타깃끼리 8dp 이상 — [Google Android 접근성 도움말](https://support.google.com/accessibility/android/answer/7101858)
- [사실] WCAG 2.2 SC 2.5.8(AA)은 24×24 CSS px, 옛 SC 2.5.5(AAA)는 44×44px — [Adrian Roselli](https://adrianroselli.com/2019/06/target-size-and-2-5-5.html), [W3C wiki](https://www.w3.org/WAI/GL/mobile-a11y-tf/wiki/Proposed_SC_Target_Size)
- [판단] 웹 게임 기본값은 두 기준 중 큰 48px. 작은 아이콘 버튼은 `padding`이나 투명 `::before`로 칸만 키운다

### 대비
- [사실] WCAG 1.4.3(AA): 일반 글자 4.5:1, 큰 글자(18pt≈24px 이상 또는 14pt≈18.66px 굵게) 3:1. 반올림 금지(4.499는 탈락) — [W3C Understanding 1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)
- [사실] WCAG 1.4.11(AA): 버튼 경계·아이콘 등 의미 있는 비문자 요소 3:1, 비활성 컨트롤은 예외 — [W3C Understanding 1.4.11](https://www.w3.org/WAI/WCAG21/Understanding/non-text-contrast)
- 확인 도구: [WebAIM Contrast](https://webaim.org/articles/contrast/)

### 모션
- [사실] Material(1판) 모바일: 일반 전환 300ms, 큰 전체 화면 전환 최대 375ms, 400ms 넘으면 느리게 느껴짐. 등장 225ms, 퇴장 195ms. 이징 표준 `cubic-bezier(0.4,0,0.2,1)`, 감속(등장) `(0,0,0.2,1)`, 가속(퇴장) `(0.4,0,1,1)` — [Material Motion Duration & Easing](https://m1.material.io/motion/duration-easing.html)
- [사실] 0.1초 안에 반응하면 "즉시·직접 조작"으로 느낌, 1초는 흐름 유지 한계 — [NN/g Response Times](https://www.nngroup.com/articles/response-times-3-important-limits/)
- [판단] 그래서 버튼 눌림은 `pointerdown` 즉시 + 80~100ms 축소, 결과 카드 등장은 225ms, 별·점수 카운트업 같은 보상 연출만 예외로 길게(600~900ms) 허용
- Material 3는 50~1000ms 토큰(Short1~ExtraLong4)을 두지만 공식 표는 직접 확인 못 함 — [Flutter M3 motion 생성 코드](https://flutter.googlesource.com/mirrors/flutter/+/0a6947049b89e7cd9b4ff899ad464ec7365f620e/dev/tools/gen_defaults/lib/motion_template.dart)

### 모서리·그림자
- [사실] Material 계열은 모서리를 몇 단계 토큰(예: 4dp·8dp …)으로 고정해 씀. 단, 큰 단계 값은 플랫폼마다 달라 이번 조사로 확정 못 함 — [Android Shapes 참조](https://developer.android.com/reference/kotlin/androidx/compose/material3/Shapes)
- [판단] 작은 게임에는 3단계(8/12/20)로 충분. 안쪽 요소 반경 = 바깥 반경 − 안쪽 여백(예: 카드 20, 패딩 8 → 안쪽 버튼 12)이면 테두리가 평행해 정돈돼 보인다
- [판단] 그림자 토큰 예: `--sh-1: 0 1px 2px rgb(0 0 0/.08), 0 1px 1px rgb(0 0 0/.04)`(버튼), `--sh-2: 0 8px 24px rgb(0 0 0/.12)`(카드·모달). 그림자 색은 검정 대신 배경색의 어두운 톤이면 더 깨끗

### 복사해서 쓰는 토큰 예시 [판단]
```css
:root{
  --s1:4px;--s2:8px;--s3:12px;--s4:16px;--s5:24px;--s6:32px;--s7:48px;
  --fs-xs:12px;--fs-sm:14px;--fs-md:16px;--fs-lg:20px;--fs-xl:30px;
  --r-sm:8px;--r-md:12px;--r-lg:20px;
  --sh-1:0 1px 2px rgb(0 0 0/.08);--sh-2:0 8px 24px rgb(0 0 0/.12);
  --ease-in:cubic-bezier(0,0,.2,1);--ease-out:cubic-bezier(.4,0,1,1);
  --t-press:90ms;--t-small:180ms;--t-enter:225ms;--t-exit:195ms;--t-screen:300ms;
  --tap:48px;
}
button{appearance:none;border:0;font:inherit;color:inherit;background:none;
  min-height:var(--tap);min-width:var(--tap);border-radius:var(--r-md);
  -webkit-tap-highlight-color:transparent;touch-action:manipulation;
  transition:transform var(--t-press) var(--ease-in),box-shadow var(--t-press)}
button:active{transform:scale(.96);box-shadow:none}
button:focus-visible{outline:3px solid var(--accent);outline-offset:2px}
@media (prefers-reduced-motion:reduce){*{animation-duration:1ms!important;transition-duration:1ms!important}}
```

## 3. '싸 보이게' 만드는 흔한 실수와 고치는 법 [판단, 근거 표기]

| 실수 | 왜 싸 보이나 | 고치는 법 |
|---|---|---|
| 이모지를 아이콘으로 남발, 크기·기준선 제각각 | 이모지는 기기마다 그림이 다르고(Apple/Google/Samsung 각자 그림) 같은 이모지도 해석이 25% 엇갈림 [사실: [CSCW 2018](https://brenthecht.com/publications/cscw2018_emojiimpact.pdf)]. 색·명암·디테일 수준이 UI와 안 맞음 | UI 컨트롤은 단색 SVG 한 세트로. 이모지는 '캐릭터·보상 장식'에만, 고정 박스(`width/height:1em; line-height:1`)에 |
| 글자 크기 난립(13·14·15·17·18…) | 위계가 안 읽힘 | 5단계 토큰만 사용, 한 화면 3단계 |
| 테두리·그림자·반경이 요소마다 다름 | '여러 사람이 만든' 느낌 | 토큰 3·2·3단계, 테두리 또는 그림자 중 하나 |
| 색이 많음(버튼마다 다른 색) | 강조가 사라짐 | 강조 1색 + 중립 회색 단계. 보조 버튼은 면 색 + 진한 글자 |
| 정렬 어긋남(아이콘과 글자 기준선, 카드 안 여백 불균등) | 눈이 바로 알아챔 | `display:flex;align-items:center;gap:8px`. 아이콘은 `display:block`(인라인 기준선 여백 제거) |
| 모든 걸 가운데 정렬 | 긴 글은 읽기 어렵고 위계가 흐려짐 | 가운데 정렬은 제목·한 줄 안내·결과 숫자만. 두 줄 넘는 글·목록은 왼쪽 정렬 |
| 기본 브라우저 스타일 노출(회색 버튼, 파란 탭 하이라이트, 글자 선택, 더블탭 확대) | '웹페이지'처럼 보임 | 규칙 15번 리셋, `user-select:none`, `touch-action:manipulation` |
| 픽셀 흐림(캔버스 확대, 0.5px 위치, 비율 안 맞는 이미지) | 흐릿함 = 싸구려 | 캔버스는 `width*devicePixelRatio`로 그리고 CSS로 줄이기, `transform` 위치는 정수로 반올림, 아이콘은 SVG |
| 버튼 눌러도 반응 없음 / `click`만 사용 | 0.1초 넘는 지연은 '고장'처럼 느낌 [사실: [NN/g](https://www.nngroup.com/articles/response-times-3-important-limits/)] | `:active` 축소 + `pointerdown` 반응 |
| 모션이 길고 제각각(500ms 넘는 페이드, `linear`) | 굼뜨고 싸 보임 | 2장 시간·이징 토큰 |
| 글이 길고 많음(카드에 3줄 설명) | 읽지 않음, 꽉 찬 느낌 | 한 줄 + 아이콘, 동시에 1개(프로젝트 규칙과 같음) |
| 숫자 흔들림(점수 바뀔 때 좌우로 움직임) | 정밀하지 않아 보임 | `tabular-nums` [사실: [MDN font-variant-numeric](https://developer.mozilla.org/en-US/docs/Web/CSS/font-variant-numeric)] |
| 안전 영역 무시(노치·홈 바에 버튼 겹침) | 마감 안 된 느낌 | `viewport-fit=cover` + `padding: env(safe-area-inset-*)` |

- [판단] 가장 안전하고 비용 0인 방법: HTML 안 SVG 묶음 바로 위에 주석으로 라이선스 문구를 넣는다(파일이 퍼져도 문구가 같이 간다). 설정 화면 맨 아래 "아이콘: Lucide (ISC)" 한 줄은 선택
- [판단] 한 게임 안에서 세트를 섞지 않는다(Lucide와 Tabler는 둘 다 24 격자·선 2px라 비슷하지만 끝 처리·비율이 미묘하게 다름). 게임랩 표준은 Lucide 하나 권장(아이콘 수 많고 기본값 `stroke-width:2`, round cap/join)

### 단일 파일에 넣는 방법 [판단]
아이콘 정의는 한 번, 쓰는 곳은 `<use>`로 — 파일 크기 줄고 크기·색이 CSS로 통일된다. 아이콘 원본은 사람이 lucide.dev에서 SVG를 복사해 path만 붙여 넣는다(설치·CDN 없음).
```html
<!-- Icons: Lucide (https://lucide.dev) — ISC License
     Copyright (c) 2026 Lucide Icons and Contributors
     Portions Copyright (c) 2013-present Cole Bemis (Feather, MIT License)
     Permission to use, copy, modify, and/or distribute this software for any purpose

     and this permission notice appear in all copies. (전문: https://lucide.dev/license) -->
<svg width="0" height="0" style="position:absolute" aria-hidden="true">
  <symbol id="i-play" viewBox="0 0 24 24"><polygon points="6 3 20 12 6 21 6 3"/></symbol>
  <symbol id="i-rotate" viewBox="0 0 24 24"><!-- lucide rotate-ccw path 붙여넣기 --></symbol>
</svg>

<button class="btn-icon" aria-label="다시"><svg class="ic"><use href="#i-rotate"/></svg></button>
```
```css
.ic{width:24px;height:24px;display:block;fill:none;stroke:currentColor;
    stroke-width:2;stroke-linecap:round;stroke-linejoin:round}
```
- 크기는 20(글자 옆)/24(단독 버튼)/32(결과 카드 큰 상징) 3단계만. 색은 `currentColor`로 글자색을 따라가게
- 채운 아이콘(별 보상 등)은 같은 symbol에 `fill:currentColor`만 바꿔 '빈 별/찬 별'을 만든다 → 이모지 ⭐ 대체
- 글 없는 버튼에는 반드시 `aria-label`

### 이모지를 계속 쓸 때 [판단]
- 쓸 곳: 캐릭터·장난감 같은 '게임 속 물건'과 보상 장식. 버튼·HUD·설정 아이콘에는 쓰지 않기
- 같은 크기 박스: `.emo{font-size:28px;line-height:1;width:1em;height:1em;display:inline-grid;place-items:center}`
- 글꼴 고정: `font-family:"Apple Color Emoji","Segoe UI Emoji","Noto Color Emoji",sans-serif`
- 한 화면에 이모지 스타일(얼굴·물건·기호) 섞지 않기

## 5. 시스템 글꼴로 정돈된 한국어 타이포

- [사실] 흔한 한국어 스택: Apple SD Gothic Neo(맥·iOS 기본 한글), Malgun Gothic(윈도, 화면 읽기용 설계), Noto Sans KR(안드로이드 등 대체) 순 — [Pretendard README의 대체 스택](https://cdn.jsdelivr.net/npm/pretendard@1.3.9/docs/en/README.md), [Microsoft Malgun Gothic](https://learn.microsoft.com/cs-cz/typography/font-list/malgun-gothic), [WordPress Trac #7969](https://meta.trac.wordpress.org/ticket/7969)
- [사실] Apple 한국 App Store·Mozilla 한국어 CSS가 `word-break: keep-all` 사용. 긴 단어 넘침 대비로 `overflow-wrap:break-word` 같이 권장 — [Apple KR CSS](https://www.apple.com/kr/app-store/styles/main.built.css), [Mozilla ko intl.css](https://www.mozilla.org/media/css/l10n/ko/intl.a6e7bf55b345.css), [달레 코딩: 한국어 줄바꿈](https://daleseo.com/css-text-wrap/)
- [사실] `tabular-nums` = 모든 숫자 같은 폭(OpenType `tnum`) — [MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/font-variant-numeric)
- 프로젝트 표준 글꼴 문서(`~/Desktop/NHC/command-center/docs/FONTS.md`)가 있으면 그쪽이 우선

```css
body{
  font-family:-apple-system,BlinkMacSystemFont,"Apple SD Gothic Neo","Malgun Gothic",
    "Noto Sans KR","Noto Sans CJK KR","Segoe UI",Roboto,sans-serif;
  font-size:16px;line-height:1.5;
  word-break:keep-all;overflow-wrap:break-word;
  -webkit-font-smoothing:antialiased;text-rendering:optimizeLegibility;
  -webkit-text-size-adjust:100%;
}
h1,h2,.title{line-height:1.25;letter-spacing:-0.02em;font-weight:700}
.num,.hud,.score,.timer,.level-no{font-variant-numeric:tabular-nums;letter-spacing:0}
.caption{font-size:12px;letter-spacing:0;color:var(--text-2)}
```
- [판단] 한글 제목은 자간 −0.01~−0.02em이면 단단해 보이고, 본문·12px 이하는 0(좁히면 뭉개짐). 영문 대문자 라벨만 +0.04em
- [판단] 한글은 같은 px에서 영문보다 작아 보이지 않지만 획이 많아 14px 미만 본문은 피하기. 12px는 보조 라벨만
- [판단] 굵게는 700 하나. 시스템 한글 글꼴은 중간 굵기가 기기마다 달라 600이 400처럼 나오기도 함

## 6. 아이 대상 게임 UI 추가 규칙

- [사실] Game Accessibility Guidelines 기본 항목: 읽기 쉬운 기본 글자 크기, 글자/UI와 배경 고대비, **고정된 색만으로 필수 정보 전달 금지**, 조작 요소를 크고 넉넉히 떨어뜨리기(특히 작은 터치 화면), 쉬운 말, 대화형 튜토리얼, 글 안내는 자기 속도로 넘기기 — [gameaccessibilityguidelines.com/basic](https://gameaccessibilityguidelines.com/basic/)
- [사실] BBC 아이용 게임 가이드: 색약·아직 글을 잘 못 읽는 아이·일시적 장애를 고려 대상으로 명시, 터치·마우스·키보드 모두로 끝까지 플레이 가능해야 함 — [BBC GEL: How to design accessible games (보관본)](https://webcf.waybackmachine.org/web/20211112060422/https://www.bbc.co.uk/gel/guidelines/how-to-design-accessible-games)
- [사실] 적록 색약이 가장 흔함 — [Filament Games](https://www.filamentgames.com/blog/the-hidden-barriers-in-game-ui-and-how-to-spot-them)
- [판단] 실무 규칙
  - 터치 56~64px, 버튼 사이 12px 이상(아이 손가락·정확도 고려, 48px 기준에서 한 단계 올림)
  - 안내는 글 대신 **손가락 아이콘 + 움직임 시범**(1회, 1.5초 이내 반복). 글은 보조 한 줄
  - 성공/실패는 색 + **모양(체크/X)** + 소리 + 움직임(통통/흔들) 중 최소 2개
  - 빨강/초록 대비에 의존 금지 → 파랑/주황, 또는 명도 차로 구분. 회색조로 캡처해 구분되는지 확인
  - 실수로 누르면 곤란한 버튼(나가기·처음부터)은 화면 구석·작게 두지 말고 확인 단계(2번 탭) 두기, 주 버튼과 24px 이상 떨어뜨리기
  - 시간 제한 안내 문구·작은 글씨 금지, 숫자는 크게(28px+)
