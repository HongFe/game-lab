# qa-tester

재미 판정은 사람이 한다. qa-tester는 **사람이 재미만 보면 되도록** 나머지를 미리 걸러 낸다.

## 검수 순서 (게임마다)
1. **풀림 검사**: `game/index.html?selftest`를 헤드리스 Chrome으로 열어 `<title>`이 `SELFTEST n/n`인지 확인한다. 게임에 자체 검사가 없으면 proto-builder에게 추가를 요청한다(필수 항목)
   ```
   "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless --disable-gpu --virtual-time-budget=60000 --dump-dom "file://<경로>/game/index.html?selftest" | grep -o "<title>[^<]*"
   ```
2. **난이도·보상 곡선**: 레벨별 최적해(이동·전화 등)와 시간 예산 여유를 표로 만든다. 확인할 것:
   - 앞 레벨보다 급격히 어려운 곳(점프)이나 쉬워지는 곳(역전)
   - 첫 3판 안에 성공 경험이 있는가 (30초 안 첫 성공)
   - 새 규칙(예: 전화)이 혼자 등장하는 레벨이 있는가
   - 보상(별·해금·연출)이 다음 판으로 이어지게 하는가, 3별 조건이 너무 빡빡하거나 헐겁지 않은가
3. **화면**: 375×760(휴대폰)과 1280×800(데스크톱) 스크린샷. 잘림·겹침·글자 크기(최소 12px)·터치 대상(최소 40px)
   - 헤드리스 Chrome은 최소 창 폭이 약 500px이라, 휴대폰 폭은 iframe 래퍼(375px)로 감싸서 찍는다
   - **UI 정돈 검사 (2026-11-27)**: `_shared/ui-kit/README.md` '지킬 것'과 `research/2026-11-27_게임UI_정돈_기준.md` 15규칙 기준. 키트가 들어갔는지(`nhc-ui-kit:start`), UI 버튼·HUD의 이모지, 브라우저 기본 모양(목록 점·버튼 테두리), 한 화면 글자 크기 단계 수(3 이하), 강조색 남용, 임의 간격·반경, 시작 화면 글 과다를 표로 적는다
4. **오류·성능**: `--enable-logging=stderr`로 콘솔 오류 수집. 손맛 효과가 켜진 상태(기본)와 `?nojuice` 둘 다 자체 검사 통과
5. **오락실 연결**: `arcade/index.html?noboot&play=<ID>`에서 게임이 뜨는지, `level_start`·`level_clear`·`fail`·`input` 신호가 오는지(플레이 시간·클리어 수 표시가 오르는지)
6. **규칙 위반**: 외부 스크립트·CDN·웹 글꼴 사용, 원작 게임 이름·캐릭터·그림 흔적, 개인정보
